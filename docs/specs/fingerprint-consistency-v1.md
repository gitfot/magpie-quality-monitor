# 基于 Codex CLI 的多模型指纹一致性监测 V1

## Problem Statement

当前插件通过固定逻辑题和 HTML/SVG 绘图题观察模型表现。一个监测对象绑定一个模型或路由及一组推理强度，下面配置多道题。这种结构适合单目标的能力观察，但不适合在同一对象内管理多个模型的指纹分布对照。

使用者希望复用 Codex CLI 和 Magpie 调用链，以较低输出量重复请求模型从 1～355 中选择一个数字，将结果分布与现成参考基准比较，并持续观察其变化。使用者不希望每次手工执行检测、查看柱状图和主观比较，也不希望必须先自行采集基准。

新增功能需要以数值和紧凑的历史方格表达分布匹配情况，同时明确区分低匹配、样本不足、调用失败、中断和没有历史，不能把渠道可用性或采样问题伪装成模型降智。

原项目的参考基准来自 API 采样，本插件经过 Codex CLI 和 Magpie，二者的可比性尚未验证。该功能只能定位为实验性分布对照，不能用分数证明模型身份、服务掺假、掺混比例或智力水平。

## Solution

在现有总览中新增独立的“指纹一致性监测”对象类型，不改变逻辑／绘图监测对象的既有行为。

一张指纹卡片管理多个受测模型／路由。每个模型行独立绑定参考基准、请求推理强度、匹配分数和历史时间轴，不计算卡片级平均分。每次模型测试包含一批独立的 CLI 采样；每批默认尝试 50 次，汇总为一个分布和一个历史方格。

基准来自随插件发布的预置库或兼容 hlwy-ai-checker 的 JSON 导入。用户不需要自行标定。基准集中管理、固定版本绑定；更新数据不静默替换已有绑定，也不重算历史。

使用完整分布的归一化 Jensen–Shannon 距离生成 0～100 的“指纹匹配度”。时间轴用五档红绿配色表达数值区间，并为无法评分的真实批次和无历史补位提供不同样式。点击方格查看本批与绑定基准的频率双柱图、统计摘要和采样明细。

所有模型调用继续经 Codex CLI。全局保持单 CLI 任务运行，指纹采样之间轮转排队，避免长期阻塞现有监测。新对象默认不启用定时；启用后默认每 24 小时一轮。指纹历史独立默认保留 30 天。

## User Stories

1. 作为插件使用者，我希望在同一总览中看到逻辑／绘图监测与指纹监测，以便统一观察不同类型的模型表现。
2. 作为插件使用者，我希望新建对象时明确选择监测类型，以免把模型指纹配置混入原有题目配置。
3. 作为已有用户，我希望原有逻辑题、绘图题、调用和历史展示保持兼容，以免新功能破坏日常监测。
4. 作为插件使用者，我希望按对象类型筛选卡片，以便在对象较多时快速定位相关监测。
5. 作为插件使用者，我希望一张指纹卡片配置多个受测模型／路由，以便统一安排一组目标的检测。
6. 作为插件使用者，我希望每个模型独立显示时间轴和结果，以免其他模型的正常表现掩盖其变化。
7. 作为插件使用者，我希望每个模型独立设置请求推理强度，以适应不同模型的支持情况。
8. 作为插件使用者，我希望同一模型能够以不同推理强度配置成多行，以便分别观察不同请求设置。
9. 作为插件使用者，我希望每个目标明确绑定一份参考基准，并能在编辑器和批次详情核对该绑定，以便知道匹配分数在与什么比较；首页模型行不重复展示基准名称及版本说明。
10. 作为插件使用者，我希望多个声称提供同一模型的渠道可以引用同一份基准，以便进行一致的参考对照。
11. 作为插件使用者，我希望增添、停用、移除和排序模型行，以便维护实际需要测试的目标及执行顺序。
12. 作为插件使用者，我希望在卡片统一配置采样次数和单次超时，以免逐行重复维护相同设置。
13. 作为插件使用者，我希望每模型默认只尝试 50 次采样，以便从可控的执行规模开始。
14. 作为插件使用者，我希望失败不自动补跑，并能在编辑器看到每轮预计 CLI 执行量，以便控制耗时和费用，而不占用首页卡片空间。
15. 作为插件使用者，我希望新对象默认不启用定时，以便先手动验证配置。
16. 作为插件使用者，我希望启用定时后默认每天执行一轮，并可调整间隔，以便按实际成本选择频率。
17. 作为插件使用者，我希望下一轮从上一轮结束后计算间隔，不补跑或叠加错过轮次，以免任务积压。
18. 作为插件使用者，我希望一键执行全部启用模型，以便运行完整的卡片轮次。
19. 作为插件使用者，我希望只对某个模型执行一整批采样，以便核查该模型而不重复测试其他目标。
20. 作为插件使用者，我希望手动测试不自动开启定时，以免意外产生持续调用。
21. 作为插件使用者，我希望关闭定时与停止当前执行是不同动作，以便准确控制未来计划和本轮任务。
22. 作为插件使用者，我希望停止本轮时仅取消本卡片的工作，并保留已完成模型结果，以免影响其他监测。
23. 作为插件使用者，我希望正在执行或排队的卡片不能重复提交，以免误点击产生重复批次。
24. 作为插件使用者，我希望所有模型任务仍然全局串行，并在指纹样本之间让其他任务获得执行机会，以免已有监测长时间停摆。
25. 作为插件使用者，我希望同一卡片按模型顺序完成整批采样，以便理解当前进度和接下来的工作。
26. 作为插件使用者，我希望区分采样中和等待队列，并查看已尝试、有效和无效数量，以免把排队误认为卡死。
27. 作为插件使用者，我希望仅将成功返回的单个范围内整数作为有效样本，以免长回答中的其他数字污染分布。
28. 作为插件使用者，我希望出现工具调用的采样被标记为无效，以免将工具生成的随机数误当成模型偏好。
29. 作为插件使用者，我希望未完成、有效样本不足或有效率过低的批次不被评分，以免不完整数据产生误导结论。
30. 作为插件使用者，我希望样本不足、中断和调用失败不被涂成最低分，以便区分数据质量与分布差异。
31. 作为插件使用者，我希望以完整数字分布得到 0～100 的匹配分数，以便不依赖肉眼比较柱状图。
32. 作为插件使用者，我希望分数明确不等于真实性概率、掺混比例或能力分，以免误解检测结果。
33. 作为插件使用者，我希望五档颜色表达数值高低，而不是宣判正常、掺假或降智，以免把显示分段当成诊断阈值。
34. 作为插件使用者，我希望每个真实方格代表该模型的一批采样，以便从连续记录中观察变化。
35. 作为插件使用者，我希望历史左旧右新、最新靠右，停机或没有执行时不补时间格，以免看到虚构的执行历史。
36. 作为插件使用者，我希望通过文字、数值、提示和标记理解状态，而不只依赖颜色，以便在不同视觉条件下使用。
37. 作为插件使用者，我希望最新批次未评分时直接看到原因，而不是静默回退成旧分数，以免误读最新状态。
38. 作为插件使用者，我希望点击方格查看本批与所选基准的双柱图，以便核查分数对应的分布差异。
39. 作为插件使用者，我希望柱图比较频率而不是原始次数，以便比较不同样本量的数据。
40. 作为插件使用者，我希望默认查看至少一方出现过的数字，并能查看完整数字范围，以免大量零柱妨碍阅读或隐藏差异。

43. 作为插件使用者，我希望在详情折叠区查看原始输出、状态、耗时、配置和 CLI 信息，以便追溯测试过程。

## Implementation Decisions

### 领域边界与执行数据

- 新增独立的指纹监测对象类型，不把指纹采样伪装成逻辑题或绘图题，不支持两类对象互转。
- 指纹对象包含公共计划和有稳定身份的有序模型行；每行包含目标、请求推理强度、基准绑定和启停状态。
- 同一目标可以使用不同请求推理强度形成不同模型行。所有模型行共享卡片采样次数、单次 CLI 超时和执行计划，第一版不提供逐行覆盖。
- 引入模型采样批次及其逐次样本的表达。一轮可以包含多个模型批次；一个模型批次对应一个历史方格，单次样本不是首页方格。
- 保存批次的固定配置、绑定基准、分布、评分方法标识、分数或无法评分原因，以及样本状态、输出和既有 CLI 元数据。概览仅提供必要摘要，详细样本按需读取，不把完整输出复制到首页状态中。
- 扩展现有本地监测服务、持久化和执行队列，不另起 Python 代理服务，也不新增直连供应商 API 的执行后端。
- 对象、模型行、批次、样本和基准之间的引用必须可明确区分，不能根据显示名称拼接历史。

### 采样协议、有效性与评分

- 使用专用、固定并可追溯的采样提示，要求从 1～355 中选择一个数字、只输出该数字且不调用工具。不得附加现有逻辑题最终答案标记或绘图指令。
- 每个样本使用一次新的独立 CLI 执行；不复用聊天上下文，不以一次生成一串数字替代独立采样。
- 采样次数按尝试预算计数，默认每模型每批 50 次。失败、超时、工具调用和格式无效均消耗尝试预算，不自动补跑或更换执行后端。
- 合格样本要求 CLI 正常完成，最终文本去除首尾空白后仅有一个表示 1～355 的整数，且没有记录到工具调用。不得在长文本中搜索第一个数字。
- 调用成功和样本有效分别记录。正常完成但格式不符或有工具调用的执行，可以是调用成功、样本无效；不能将其混作低匹配或逻辑答错。
- 只有完成全部预定尝试、有效样本至少 40 个、有效率至少 80% 的批次可以评分。该门槛是最低展示规则，不是统计可靠性保证。
- 中断或未达门槛的批次保存已获得的样本、分布和原因，但不产生数值匹配分数。没有开始采样的目标不制造失败批次。
- 有效数字形成长度为 355 的经验频率分布。参考分布和本批分布以完整概率分布比较，不要求参考样本数等于本批样本数。
- 指纹匹配度等于 100 乘以一减归一化 JS 距离。归一化 JS 距离为以 2 为对数底的 Jensen–Shannon 散度的平方根；若使用自然对数，则先除以 ln(2) 再开平方。
- 分数范围为 0～100；相同观测分布得 100，支持集完全不相交得 0。正确处理零概率，避免 NaN、无穷值和显示越界。
- 不额外加权众数数值距离、均值或标准差。统计摘要只解释数据，不另作真假或降智判定。
- 不沿用上游 96／92 的诊断阈值，也不根据最高匹配基准推断实际模型身份。
- 不承诺当前 CLI 已验证温度、随机种子、协议级输出上限或服务端实际推理强度可控。继承的 Agent／MCP 环境和实际命中模型仍可能未知；如实保存可获得的元数据与限制。

### 调度、进度与取消

- 全局始终最多运行一个 CLI 任务。同卡片按配置顺序完成模型 A 的整个批次后，再开始模型 B。
- 指纹每完成一个样本，其下一次采样排到共享队列尾部；其他已有监测任务可以在样本之间运行。没有其他任务时连续采样，不引入人为等待或并发。
- 轮转不强行中断已运行任务。指纹模型行区分采样中与等待队列，并显示已尝试、有效、无效数量。
- 指纹对象新建时定时关闭。启用后的默认周期为 24 小时，允许调整；从上一轮结束后计算下一轮间隔，不补跑、不叠加未完成对象的新轮次。
- 手动执行整轮测试全部启用模型；单模型入口执行该行的一整批采样。手动执行不会自动启用定时。
- 同卡片存在已排队或运行任务时，禁止新增整轮或单模型执行，前后端均防重复提交。
- 关闭定时只阻止后续自动轮次，不停止已排队或执行中的本轮。此语义仅适用于新增指纹对象，不静默修改现有监测的暂停行为。
- 停止本轮取消属于本卡片的排队工作，并中断其在途 CLI，不能中断其他卡片。保留已完成模型结果，当前未完成批次标记中断，剩余未开始模型不增加失败格。
- 停止 CLI 不保证供应商停止执行或停止计费，界面不得暗示退款或零成本取消。
- 已排队和在途轮次沿用冻结的配置快照；编辑不修改该轮采样条件或剩余模型清单，影响后续新轮次。

### 基准库与导入

- 页面级集中基准库提供预置数据、预览、兼容上游导出格式的 JSON 导入和归档，不提供自行采样／标定入口。
- 预置数据以随插件发布的固定快照分发，第一版不后台自动同步远程基准。分发时保留来源和许可证说明，核对上游数据授权要求。
- 展示基准名称、来源、采集时间和样本数；这些来源信息不构成厂商认证。没有来源证明时不声称已认证为官方模型数据。
- 导入验证数据结构、数字范围、分布维度和有限非负数值等必要约束；无效导入不能覆盖或破坏已有基准。以数据处理 JSON，不执行其内容。
- 相同内容幂等复用，不同内容形成另一份基准；不能仅按名称覆盖。模型行绑定固定基准版本，导入或插件更新不自动迁移其引用。
- 明确切换基准才影响后续新轮次。历史批次固定保留当次参考及评分结果，不因基准重命名、归档、更新或切换重新计算。
- 仍被对象或历史引用的基准只允许归档，不能直接删断引用；归档不破坏已有引用。基准库不随普通执行或指纹批次保留期清理。

### 总览、卡片与详情

- 在现有新建入口选择逻辑／绘图监测或指纹一致性监测；同页并列展示，以类型标签和“全部／逻辑与绘图／指纹一致性”筛选区分。
- 现有对象不自动迁移为新类型；现有数据、执行后端和判分行为保持兼容。
- 采用已确认的 A 方案：原生紧凑卡片。两类监测卡片共用卡片操作栏、状态标识、运行按钮和时间轴组件，而不是仅模拟相似样式；类型差异通过数据及动作适配提供。
- 两类卡片暂停时统一显示“已暂停”，恢复入口统一叫“启用”，历史入口统一叫“历史”，行级手动执行统一叫“运行”，整卡执行统一叫“执行一轮”。已启用时，旧卡保留“暂停监测”，指纹卡保留“关闭定时”；只统一展示文案，不静默修改已确认的取消语义。指纹卡存在任务时另提供“停止本轮”。
- 每个模型一行，显示名称、目标、请求推理强度、最新结果、有效样本数、单模型执行入口和独立执行序列。不显示卡片级平均匹配分数；移除首页的“固定参考基准：名称 · 版本”说明行，但编辑器与详情保留固定绑定及来源信息。
- 首页指纹卡不设置预算／耗时／筛选的附加说明栏。每模型尝试次数、每轮尝试量、启用后的每日预计量及可获得的上轮耗时位于编辑器，单批耗时位于详情；估计为 CLI 执行规模，不承诺等于供应商实际请求数或金额。
- 每个真实方格代表某模型批次，左旧右新、最新靠右，随可用宽度展示最近记录；停机和没有执行时不补时间桶。中性补位不代表真实记录。与逻辑题复用同一宽度观察和容量计算、18px 方格、实心灰占位、配置分界、数量及最新时间页脚；配置分界不能额外挤占未计入容量的宽度。
- 有效分数保留五档数值区间，采用维护者最终手动确认的配色：0～不足60 为宿主失败红色的75%，60～不足80 为失败红色的50%，80～不足90 为失败红色的25%，90～不足95 为逻辑题正确方格色的70%，95～100 为逻辑题正确方格色的100%；余量与卡片背景色在 sRGB 中混合。逻辑题正确方格色本身为宿主绿色的48%与背景混合，不改变既有逻辑题颜色。
- 时间轴与图例使用相同色阶，随明暗主题调整；颜色变量支持 Hex 色值，不能把方格尺寸变量当作颜色。红绿只是数值呈现，不表示已证实的正常、异常、掺假或降智；悬停文字和数值仍须独立可读。
- 无法评分的真实批次用斜纹或警示标记；无历史补位复用逻辑题的实心灰占位，与真实未评分记录区分。悬停和可访问名称提供分数、时间、数量和状态，不只依赖颜色。
- 最新批次无法评分时显示未评分及原因，不静默回退到旧分数冒充最新。首页该模型行没有保留记录时显示暂无结果，不因历史弹窗筛选而隐藏其最新状态。
- 点格打开只读批次详情；首页不展开柱状图。详情包含目标、时间、当次基准、分数或原因、有效／无效数量、耗时及统计摘要。
- 图表以数字为横轴、频率为纵轴，对每个数字并列显示本批与基准；默认显示至少一方非零的数字并按数字升序排列，支持查看完整 1～355 范围。悬停显示具体频率。
- 未评分批次仍可查看已取得的分布。采样明细及配置／CLI 信息位于折叠区，不展示全库模型排名或自动身份猜测。
- 顶部统计继续覆盖全部对象，不随类型列表筛选变化。“今日请求”明确为“今日 CLI 执行”，指纹按单次采样尝试而非批次数计数，不能另外把进程版本探测计成一次采样。调用成功率与样本有效率、匹配分数分别表达。
- 延续宿主主题、已有内嵌浏览器和多语言能力，保证紧凑及窄窗口下可用。图表实现遵守既有本地脚本与 CSP 边界，不依赖上游网页的外部 CDN 脚本。

### 历史、筛选与生命周期

- 指纹批次历史独立默认保留 30 天，可在设置中调整；不改变既有逻辑／绘图保留设置。
- 首页指纹卡从该模型行全部保留历史中展示最近 N 批，不按时间范围或当前配置另行筛选。原有页面级统计筛选保持原作用范围，不扩展至指纹首页结果。
- 每张指纹卡的“历史”弹窗提供最近 7 天、最近 30 天和全部保留历史，以及全部配置／仅当前配置，初始为全部保留历史和全部配置；筛选变更后回到第一页。范围只是历史列表过滤条件，不改变方格的实际批次语义。
- 历史弹窗的时间和配置筛选仅作用于弹窗列表及分页，不影响首页最新结果、时间轴或全局统计。首页最新结果与时间轴均使用该模型行全部保留历史，并保留可辨认的配置分界。
- 批次的分布、分数、配置快照和样本明细整体保留、整体清理，避免详情中的样本先于批次过期。不得清理正在进行的批次，也不得随此清理基准库。
- 模型、请求推理强度、绑定基准或采样条件变化形成可辨认的配置分界；改名、排序、周期、启停状态及兄弟行变更不切断未改变模型行的历史。
- 移除模型行仅影响后续配置，原记录仍可从整卡“历史”入口访问。重新添加为新行，不根据名称或目标自动接回已移除行。
- 删除整卡及历史须明确二次确认，取消其任务并清理其记录，防止迟到结果复活已删对象；不连带删除共享基准。

### 安全、兼容与交付边界

- 延续现有回环 API 的鉴权、Host／Origin 检查、私有本地存储、输出脱敏和内嵌安全边界。
- 基准元数据、导入内容和模型输出均作为不可信文本处理；图表、详情和错误提示不能引入脚本执行或秘密泄漏。
- 不新增供应商凭据管理，不读取用户日常凭据用于测试，不改变用户现有 Codex 配置，不承诺只读 CLI 已普遍禁止工具或网络。
- 在正式完成可用性和可比性验证前明确标注“实验性分布对照”。该标识和验证通过均不构成模型身份或能力认证。

## Testing Decisions

### 主测试边界

- 优先复用现有私有监测服务 API 作为主自动化验收边界，启动真实监测服务和临时本地持久化，使用现有可控时间与模拟 Codex CLI 夹具驱动输入。
- 从创建、配置、绑定、执行、状态、详情、历史和清理等公开行为验证结果，不直接断言私有函数、队列数组、数据库表布局或内部类调用顺序。
- 不为单元测试新增生产专用测试 API。仅在现有夹具不足时扩展测试夹具，使其输出可编排的 JSONL 事件、纯数字、无效文本、工具事件、失败和阻塞状态。
- 内嵌浏览器测试复用同一服务及合成批次数据，是 UI 的必要外层验收，不再另造一套脱离服务的功能模型。
- 真实 Codex／Magpie 验证为独立、显式授权的手动关卡，不能作为默认自动化测试的隐藏依赖。

### 可观察行为覆盖

- 对象创建和配置：两类对象兼容、新对象默认暂停、50 次默认预算、每行强度与基准绑定、同目标不同强度、增删排序、重复提交及无效保存不破坏已有配置。
- 采样：每个样本独立执行、专用提示不附加逻辑／绘图要求、纯数字与范围边界、长文本拒绝、工具调用无效、失败和超时消耗预算且不补跑、不换后端。
- 评分门槛：预定尝试完成与未完成；有效样本为39与40；有效率刚低于80%与恰为80%；在样本数或有效率任一不足时不评分。使用不同预算分别验证两个门槛，不只依赖默认50次。
- 分布与分数：通过可控样本和导入基准验证频率、零概率处理、相同分布100、完全不重合0、交换分布结果对称、已知中间分布的数值结果，以及样本量不同但频率相同不改变匹配度。预期值独立计算，不调用被测评分实现生成期望。
- 状态和取消：排队与执行进度、无效但调用成功、停止在途 CLI、保留已完成模型、当前批次中断不评分、未开始模型不制造记录、删除后迟到结果不复活。
- 公平调度：多个模型按行顺序完成、全局不并发、普通逻辑／绘图任务能在指纹采样之间运行、无其他任务时持续推进，不依赖真实时长碰运气。
- 定时：默认关闭、手动不启用定时、默认24小时、完成后再计算间隔、不叠加、不补跑、关闭定时不停止本轮；原对象原有暂停行为不回归。
- 基准：兼容导入、畸形数据拒绝、相同内容幂等、同名不同内容不覆盖、已有引用不随发布或导入变化、归档保持引用、引用中不能删断、来源和许可证信息保留。
- 历史：运行快照不可变、基准和评分不重算、配置分界与当前配置过滤、兄弟行变更不影响原行、移除行保留历史、重新添加不拼接、整卡删除隔离、批次及明细同保留期且基准独立。
- 顶部统计：CLI 尝试量不按批次低估，不重复计算版本探测，调用成功与样本有效分离，类型筛选不改变全局统计范围。
- UI：新建类型选择、公共设置与模型列表、整轮／单模型入口、停止与定时的独立语义、每模型独立时间轴、无卡片平均分、真实格／无评分格／补位格区别、色阶全部边界、最新无评分不回退、悬停及可访问说明、详情频率双柱图和完整数字范围。
- 共享 UI：两类卡片暂停状态与公共按钮文案一致；时间轴方格尺寸、灰色补位、容量随宽度变化、配置分界及数量／时间页脚一致；允许类型特有的状态和详情。验证最终红绿五档在明暗主题中的实际混色、时间轴与图例一致，且尺寸变量不参与颜色计算。
- 首页与历史：确认首页没有每卡时间下拉、预算说明栏或固定参考基准说明行；历史筛选与分页不改变首页最新结果和时间轴；预算和基准信息仍可从编辑及详情核对。
- UI 与兼容回归：内嵌沙盒保存、窄窗口与主题切换、既有语言支持、旧逻辑题／绘图对象、历史导出、接入恢复与失败展示保持可用。不要把精确 DOM 层级或私有 CSS 类名作为业务合同。
- 安全：新读写操作继续验证鉴权及来源，恶意导入文本和输出不能执行脚本，秘密不进入摘要、错误或公共产物；正常测试不使用真实账户目录或公网供应商。

### 现有先例

- 服务夹具已经覆盖默认配置、手动执行、控制时钟、重启持久化、定时和导出，可作为主边界的既有基础。
- CLI 夹具已经覆盖 JSONL、最终消息、工具事件、用量、协议失败、超时和 Windows 进程树取消，可扩展为数字采样输入。
- 现有历史兼容与序列测试已经覆盖兄弟项不影响历史、实验条件变化、不可变快照、真实方格、停机不补格和最新靠右，可复用相同的外部行为思路。
- 内嵌浏览器保存、历史渲染、接入恢复和安全测试可作为 UI 和边界回归先例；不要求迁移或重写现有测试结构。

### 真实验证关卡

- 开跑前单独确认目标、批次数、每批尝试预算及费用范围，不从本规格或 ready-for-agent 标签推导付费授权。
- 检查纯数字有效率、工具调用、每批耗时和报告的 Token；真实用量未知时显示未知，不凭空估算实际费用。
- 对同一目标重复多批50次采样，观察自然波动，并对预置参考的来源和执行链路差异给出限制说明。少量实验不能生成未经支持的误报率、真实性概率或身份保证。
- API 参考与 CLI 结果稳定不匹配时，不自动归因于换模；如果采样或区分度不成立，调整实验设计或保留明确限制，不靠放宽规则或重涂颜色包装成有效检测。

## Out of Scope

- 自行采集、标定或自动滚动学习参考基准。
- 后台自动同步远程基准，或静默更新已有模型绑定。
- 直接供应商 HTTP API 执行后端、Python 代理服务、新增供应商登录或凭据管理。
- 将一次输出多个数字视作多次独立采样。
- 并发模型调用、自动补齐有效样本、失败重试、自动换模或执行后端回退。
- 卡片级平均匹配分数、全库模型排名、自动识别实际模型、掺假比例、真假概率和智力鉴定。
- 沿用上游众数距离权重、96／92降智阈值或替换判定规则。
- 每个模型单独覆盖采样次数、超时或定时计划。
- 两类监测对象互转、改写旧记录或自动拼接重新添加模型的历史。
- 新增桌面、邮件、Webhook 等通知功能。
- 不经单独授权的真实付费模型调用、使用用户日常账户配置运行自动化测试，或仅凭模拟测试宣称检测方法已被实证验证。

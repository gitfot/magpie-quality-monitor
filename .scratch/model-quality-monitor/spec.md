# Codex降智检测：Magpie 内嵌 Codex CLI 监测插件

Status: ready-for-agent
Date: 2026-10-23
Updated: 2026-10-26
Feature: model-quality-monitor

## Problem Statement

用户在 Windows 本机运行 Magpie，通过已配置的供应商模型和路由使用 LLM，希望定期用固定逻辑题与 HTML/SVG 绘图题观察回答表现，而不是每次手工提交问题、保存回答、比较历史。

目前缺少一个内嵌于 Magpie、可以管理多个测试项、定时执行并保留只读历史的本地工具。调用成功不代表答案正确，格式合法也不代表绘图质量优秀；超时、限流、答错、输出截断以及未执行的监测空档必须区分。

插件显示名称为“Codex降智检测”，保留原内部标识和数据目录；不根据少量固定题目宣称模型整体降智、供应商换模或服务掺假。它展示可核查的请求结果、答案判定与作品，帮助用户自行比较。

## Solution

开发一个无需修改 Magpie 核心源码的 Bun 宿主插件，在 Magpie 内嵌页面提供本地监测界面。按“监测对象 → 多个测试项”组织配置，通过已接入 Magpie 的 Windows 原生 Codex CLI 定时执行，将结果及当时的配置快照保存在本机。唯一执行链路为“插件 → Codex CLI → Magpie → 模型／路由”，不保留插件直接请求网关的执行方式。

- 逻辑题：使用本地标准答案自动判定，展示正确率和各测试项的时间轴，点击查看只读详情。
- 绘图题：让文本模型生成 HTML/CSS/SVG，隔离渲染作品；首页展示最新成功作品，历史画廊每页 20 张。不展示绘图质量评分或通过状态。
- 默认每 30 分钟执行一轮，新建监测对象初始暂停；全插件串行，不由插件自动重试。
- 默认保留 5 天完整记录，可调整并导出 JSON；历史记录不因后续修改配置而改变。
- 以 Windows 原生 Codex 的 Magpie 接入为前提，模型只能从该 Agent 的可见目录快照选择；允许刷新延迟，不要求与 Agent 页实时严格同步。接入未知或目录读取失败时停止新执行，不回退。
- 编辑后时间轴和作品连续可见，默认统计所选时间范围内全部配置历史并标明跨配置，允许筛选仅当前配置。
- 绘图缩略图下展示“创建于”、耗时（分钟，两位小数）和单次会话 Token（k，两位小数），始终对应当前展示作品。

这是个人本地使用的第一版，不包含公共监测站点、多用户系统或独立常驻后台服务。

## User Stories

1. 作为本地 Magpie 用户，我希望直接安装插件而不修改 Magpie 核心源码，以便继续使用官方软件。
2. 作为用户，我希望从 Magpie 内部打开监测界面，以便不必另开一个管理应用。
3. 作为用户，我希望监测只在原生 Codex 已接入 Magpie 且可验证时执行，以便使用与日常 Codex 一致的模型接入。
4. 作为用户，我希望未接入或断开连接时监测暂停并解释原因，以免误以为模型正在被测试。
5. 作为用户，我希望创建有名称的监测对象，以便区分不同用途的模型或路由。
6. 作为用户，我希望选择某供应商的具体模型，以便单独测试该目标。
7. 作为用户，我希望选择 Magpie 路由，以便观察正常路由策略下的最终回答表现。
8. 作为用户，我希望为监测对象设置推理强度，以便在相同条件下重复测试。
9. 作为用户，我希望为同一模型的不同推理强度创建独立监测对象，以便比较结果。
10. 作为用户，我希望在一个对象下添加多个逻辑题和绘图题，以便覆盖多种能力。
11. 作为用户，我希望逐个启用或停用测试项，以便控制每轮实际执行内容。
12. 作为用户，我希望每个测试项使用固定提示词，以便比较同一题目的历史表现。
13. 作为用户，我希望修改配置前后保留各自版本，以免把不同条件的结果混为一谈。
14. 作为用户，我希望新建监测对象默认暂停，以免创建过程中意外消耗额度。
15. 作为用户，我希望设置执行间隔，默认 30 分钟，以便控制监测频率。
16. 作为用户，我希望启用前看到估算的每日请求数，以便理解额度消耗。
17. 作为用户，我希望手动立即执行完整一轮，以便验证当前配置。
18. 作为用户，我希望只手动执行某一个测试项，以便针对性复查。
19. 作为用户，我希望手动重测生成新记录，以便原失败结果不会被覆盖。
20. 作为用户，我希望所有监测请求串行执行，以便减少并发限流与资源争用。
21. 作为用户，我希望设置单次请求超时，默认 5 分钟，以免一次挂起阻塞后续工作。
22. 作为用户，我希望失败请求不被插件自动重试并掩盖，以便看到真实的调用稳定性。
23. 作为用户，我希望上轮未完成时跳过新轮并说明原因，以免堆积重复任务。
24. 作为用户，我希望退出或休眠期间的空档不被算作模型失败，以便统计不失真。
25. 作为用户，我希望恢复运行后不补发一串历史任务，以免突然消耗大量额度。
26. 作为用户，我希望暂停后不再启动后续请求，但允许已发请求保存结果，以免丢失已消耗额度的回答。
27. 作为用户，我希望每次测试使用全新上下文，以免前一轮答案影响本轮表现。
28. 作为用户，我希望测试不使用联网、工具或会话记忆，以便观察固定请求条件下的回答。
29. 作为用户，我希望逻辑题的标准答案只保存在本地用于判分，以免把答案泄露给被测模型。
30. 作为用户，我希望为逻辑题填写标准答案和多个等价答案，以便表达允许的准确答案形式。
31. 作为用户，我希望看到附加的最终答案格式要求，以便知道实际发给模型的完整内容。
32. 作为用户，我希望只从最终答案标记提取答案，以免正文中的数字或否定句被误判为正确。
33. 作为用户，我希望区分错误答案、格式不符合、调用失败和明确截断，以便定位异常原因。
34. 作为用户，我希望为不同测试项设置输出 token 上限，以便平衡完整性与费用。
35. 作为用户，我希望绘图作品安全地显示 HTML、SVG 和 CSS 动画，以便观察排版、细节与指令遵循。
36. 作为用户，我希望查看模型原始输出和提取记录，以便插件不会静默修补并美化模型表现。
37. 作为用户，我希望绘图题只展示作品而不做主观自动评分，以免把格式合法误当作质量优秀。
38. 作为用户，我希望每个绘图题默认展示最新成功作品及其真实生成时间，以便快速观察最近表现。
39. 作为用户，我希望请求失败时保留旧作品但单独提示新错误，以免误认旧图为本次生成。
40. 作为用户，我希望通过历史按钮打开该绘图题独立的画廊，并保留提示词变更前后的作品及版本标记，以便连续比较历史。
41. 作为用户，我希望画廊按新到旧分页，每页 20 张，以便浏览历史而不过量加载内容。
42. 作为用户，我希望点击作品放大查看并保留动画，以便观察细节。
43. 作为用户，我希望失败记录不占画廊的作品名额，同时可以查看失败详情，以便画廊和故障信息各自清楚。
44. 作为用户，我希望逻辑题展示时间轴、调用成功率和答案正确率，以便区分服务稳定性与答题表现。
45. 作为用户，我希望默认查看最近 24 小时并可切换 7 天，以便按时间观察变化。
46. 作为用户，我希望状态同时有文字或图标而不只靠颜色，以便清楚理解每条记录。
47. 作为用户，我希望历史详情只读并保存当时配置，以免后续编辑改变历史事实。
48. 作为用户，我希望路由目标与实际命中模型分开显示，以免把回退成功误认为指定主模型成功。
49. 作为用户，我希望无法获取的实际命中信息明确标记未知，以免系统猜测供应商或模型。
50. 作为用户，我希望默认只保留 5 天记录且知道清理规则，以便控制本地存储占用。
51. 作为用户，我希望导出历史 JSON，以便在自动清理前留档。
52. 作为用户，我希望删除监测对象前确认会同时删除测试项与历史，以免误删。
53. 作为用户，我希望异常仅在插件内提示，以免第一版引入外部通知配置与打扰。
54. 作为用户，我希望网关密钥不进入页面、模型生成代码不能访问管理界面，以便保护本地访问权限。

## Implementation Decisions

### 1. 架构和职责

- 使用一个同时具有服务端入口、页面入口与 Agent 接入适配能力的插件包。服务端在 Magpie 管理的 Bun 宿主内运行，不提供独立 companion 作为第一版架构。
- 按职责划分为接入与目录、监测配置、串行调度与执行、逻辑答案判定与作品提取、本地记录存储、受鉴权的页面服务与预览。保持接口简单，不为每个职责引入独立进程或复杂框架。
- 对外测试边界优先是完整插件页面与插件自己的服务接口，不需要向 Magpie 核心增加接口。
- 后台仅监听本机回环地址。页面入口使用已验证的 HTML 自身导航加载本地界面，目标页面完成 Magpie 页面握手；保留父框架的沙盒限制。
- 生产实现需要解决服务就绪顺序、端点发现、宿主重启后的页面恢复、可信资源交付与包更新后的入口重建，不能直接复制原型的临时端点处理作为成品。
- 插件停用、宿主重启及旧宿主退役时，不得产生多个调度者或重复执行。处理重叠宿主与退出属于实现验收要求，不因原型定时器曾成功运行而视为已经解决。

### 2. Codex 接入与唯一 CLI 执行

- 只通过本机 Windows 原生 `codex exec --json --ephemeral` 执行，不支持插件直连网关，不调用其他执行后端。CLI 不可用或拒绝参数时明确失败，不自动回退、不修改参数重试。
- 要求原生 Codex 已接入 Magpie；WSL Codex 的接入状态不能替代。插件不再要求自己的 Agent 接入，不使用原“降智监测”Agent 的模型目录或密钥。
- 不修改 Magpie 核心、不调用私有 GUI API、不修改 Codex 配置、不读取供应商登录文件或自行实现认证。后台只读必要配置，CLI 使用自身认证；凭据不进入页面、错误详情、日志或导出。
- 模型只允许下拉选择 `magpie models codex` 返回的该 Agent 可见目录快照，支持其中的供应商模型和路由；不自由填写、不扩大到全部供应商目录。“8 个”是当前动态数量，不是固定上限。
- 公共 CLI 当前输出人类文本，须使用经过验证的版本／格式适配，排除隐藏项说明和摘要中的模型 ID。命令失败、格式未知或解析失败视为读取失败，不能当作空目录或回退到插件自身目录。
- Magpie CLI 发现顺序为显式绝对路径、当前 Windows Magpie 宿主的可执行文件、PATH；支持下载版 `magpie-windows-amd64.exe`／`magpie-windows-arm64.exe`，不要求用户重命名或加入 PATH。宿主路径只按父 PID 读取并缓存，不扫描无关进程或读取命令行；读取失败时尝试 PATH，仍可手动设置。显式无效路径不静默回退。发现不修改设置或对象启停，所有候选仍须通过版本、目录和接入校验。
- 找不到 CLI、无法运行 CLI、版本不支持、目录命令失败及目录格式不支持须分别提示；不把 CLI 路径问题误报为 Codex 未接入。目录保留完整模型名称和 `ultra` 等已知推理强度，不把强度尾缀并入名称。
- 打开配置弹窗、手动刷新及每轮执行前尝试刷新目录，显示更新时间；允许延迟，不要求实时推送或完整复刻 Agent 页状态。每个对象固定选择一个模型，不随 Codex 当前默认模型改变。
- 每次打开／重新加载插件页面，在首次读取页面状态后自动后台刷新一次原生 Codex 接入与目录，不等待监测对象到期或用户手动操作；已有历史、统计和作品先展示，不阻塞首页。状态轮询不反复触发目录刷新；自动、手动与编辑弹窗刷新复用同一在途请求。
- 刷新期间首页按钮显示旋转图标与“正在刷新…”，禁用重复点击；页面状态显示“正在检查原生 Codex 接入与模型目录…”，首次读取中不表现为接入失败。编辑弹窗与首页的刷新反馈保持同步，不替换草稿或改变焦点。
- 刷新成功后更新接入状态与目录时间；失败后停止 loading、恢复按钮，显示具体失败原因并允许手动重试，不新增无限自动重试。保留原有历史、启停和调度规则，不放宽任何执行前校验。
- 新建／编辑立即打开表单，以已有目录快照展示模型，后台异步刷新；无快照时也不等待 CLI，模型区域显示加载状态。同一页面的并发刷新复用在途请求，保留手动刷新入口。完成／失败只更新目录、状态和更新时间，不重建表单，不覆盖草稿、焦点或所选目标，也不重新打开已关闭的弹窗。目录不可用或目标移除时明确提示，保留原目标，不自动改选；缓存不作为执行许可。
- 模型控件合并为一个可用键盘操作的下拉框：收起时显示“模型名称 · 完整 ID”，展开直接选择，不另设可见只读模型框或“从 Codex 目录选择”按钮。保留五种界面语言及窄屏布局。
- 接入判定只承诺经过验证的原生 Codex 模式；不能仅凭 endpoint 猜测已接入。未知配置、覆盖／漂移、目录失败、模型移除均阻止手动和定时新执行，显示原因，保留配置、历史和作品。不将等待状态伪装成调用失败。
- 条件恢复后，原本启用的对象恢复监测，不补跑空档；原本手动暂停的对象仍暂停。已经启动的测试可以按原快照完成保存。
- 路由使用 Magpie 已有分类、重试与回退，不由插件绕过或重写。
- 记录请求目标；只有可靠获得实际命中信息时才记录并展示，否则标记“未获取”。不能根据请求里的路由名称推断实际回答者。
- 每次请求独立，无历史消息、联网搜索、工具调用或插件会话记忆。发送内容仅为题目及可见的输出格式要求；不发送标准答案。
- 默认逻辑题期望输出上限 8,192 token，绘图题 16,384 token，可逐测试项调整。CLI 无法强制某参数时明确标记能力限制，不将期望上限、请求推理强度冒充上游实际执行参数；CLI 工具策略和观测到的工具事件如实记录，不宣称只读沙盒等于禁用所有工具。
- 上游拒绝参数时保留错误，不静默降档、删参数或修改参数重试。只有接口明确给出截断信息时才判为明确截断；不能只凭回复长度猜测。

### 3. 数据模型与版本

- 监测对象拥有稳定身份、名称、目标类型与标识、推理配置、执行间隔、启停状态及测试项集合。
- 测试项拥有稳定身份、逻辑或绘图类型、名称、固定提示词、启停状态、输出上限；逻辑题另有标准答案及等价答案集合。
- 调度信息与执行记录分离。未执行的监测空档、上轮未完成而跳过的轮次，不伪装成模型调用结果。
- 执行记录保存时间、配置版本与不可变快照、完整实际请求内容、原始回答、调用状态、判定或提取信息、耗时，以及可靠可获取的 token 用量等运行信息。
- 请求参数与本地判分配置分别存储，避免导出或构造网关请求时把标准答案混入请求。
- 对象或测试项配置修改只影响下一轮，当前轮次沿用已确定的配置；已发请求按旧快照完成。历史不重新套用新答案、新提示词或新目标。
- 修改题目、答案、模型、推理配置等不改变对象／测试项身份，不覆盖、重判或隐藏原记录。首页时间轴、最新作品和画廊按稳定身份连续展示，包括原直连后端的记录；标明配置变更和历史后端，不改写历史标签。
- 统计默认包含所选时间范围内全部配置记录；存在多种实验条件时标明“跨配置统计”，允许筛选“仅当前配置”。历史始终按执行时答案判定，不套用新答案。
- 已有 CLI 对象保留启停设置，仍受新接入检查约束；旧直连对象停止新执行，保留身份、测试项与历史，显示待确认转为 CLI。只有用户明确保存转换、且目标在 Codex 目录中后才可启用，不静默自动切换消耗额度。
- 暂停停止后续请求启动，允许当前请求完成并保存。删除需确认，移除对象、测试项和历史；删除后不能因旧请求回调重新生成该对象的可见历史。

### 4. 调度与生命周期

- 默认每 30 分钟一轮，可调整。新建默认暂停，主动启用前展示按启用测试项和周期估算的每日请求数；该估算不承诺包含 Magpie 路由内部重试的额外调用。
- 全插件同一时刻只执行一个测试请求。一轮依次执行对象下启用的测试项；多个对象与手动执行共享串行执行约束。
- 默认单次请求超时 5 分钟，可调整。不由插件自动重试失败请求。
- 提供立即运行一轮与单独运行某个测试项。题目启用开关仅控制定时与完整一轮执行；停用的逻辑题和绘图题仍可通过卡片按钮单独运行一次，不改变题目／对象启停、配置版本或下次执行时间。每次手动重测为新执行，不覆盖旧记录，不绕过接入检查或全局串行限制。
- 某对象上轮未完成又到期时跳过新轮并记录“上轮未完成”，不无限积压该对象轮次。
- Magpie 退出、电脑休眠或宿主不可用期间不补发历史轮次；恢复后若已过期，仅执行一轮新的测试再继续计时。未启用或未接入的对象不能因此自动运行。
- 展示最近执行与下次执行，卡片底部不展示监测空档／跳过等事件列表；事件仍保存并按既有导出和保留期规则提供。空档不纳入请求成功率，也不计作答错，不改变停机不补跑策略或其他连接／绘图异常提示。
- 不将存储失败、连接未知或宿主中断伪装成成功结果。进程恢复后应能读取已保存的历史，而不是只展示本进程内存数据。

### 5. 逻辑题判定

- 在编辑页展示将追加的输出要求：先给出解题过程，最后单独一行使用 `FINAL_ANSWER:` 标记最终答案。完整发送内容保存于历史。
- 第一版支持单值标准答案与显式配置的多个等价答案，只做首尾空白等保守规范化，不进行语义模糊匹配。
- 仅从最终答案标记提取，不在整段回答中搜索某个数字或关键词。无法唯一、可靠地提取最终答案时，不判通过；标记缺失等情况归为格式不符合。
- 区分调用状态与答题判定。可明确表达调用失败、正确答案、错误答案、答案格式不符合与输出被截断；调用错误和截断不冒充答案错误。
- 首页分别显示调用成功率和答案正确率，明确分子、分母及异常类别，避免用一个百分比混淆调用与答题表现。

### 6. 绘图、提取和预览

- 绘图为文本模型输出完整 HTML，使用 HTML/CSS/内联 SVG，不调用图片生成 API，不要求 PNG 文件。
- 提示词明确禁止 JavaScript 与外部资源。支持 CSS 动画，不支持依赖脚本的 Canvas 动画或交互应用。
- 可从 Markdown 代码围栏提取作品，但保留原始回答及提取说明，不静默补全或修复生成代码。
- 不展示绘图质量分数、质量通过状态或“智力正常”结论。安全处理与内容提取是预览前置条件，不等同于质量评价。
- 生成内容在独立、更严格的预览上下文渲染，禁用脚本、联网、表单与跳转，不注入管理界面 DOM，不获得界面授权信息或网关凭据。
- 每题首页展示最新成功渲染作品及其真实生成时间。新请求失败时保留旧作品，在区域外提示本次错误；无作品时显示空态与原因。
- 图注使用“创建于”，其下显示“耗时 X.XX 分钟 · Token Y.YYk”。指标属于当前缩略图对应的执行，而非最新失败尝试或对象累计值。
- 耗时为测试开始至结果完成的记录时间差，包含 CLI 探测／启动、执行、通信和结果处理，不含排队与缩略图截图；除以 60,000 并保留两位小数。
- Token 为该次独立 CLI 会话报告的 `input_tokens + output_tokens`，除以 1,000 并保留两位小数；缓存输入和推理输出子项不重复相加。缺少完整用量时显示“—”，不估算、不显示为 0。旧图保留时其指标不变，新失败单独提示。
- 修改提示词后旧作品继续展示；作品实验条件与当前不同则标注“来自旧配置”。历史画廊保留同一测试项各版本作品，并可在只读详情核查当时提示词和后端。
- 明确截断的回答不进入完整作品画廊；原始回答和失败原因仍保存在执行记录中。
- 每个绘图测试项有独立历史画廊，按新到旧分页，每页 20 张，最后一页允许不足 20 张；单页最多加载该页预览，不一次加载全部历史。
- 点击作品放大并查看只读详情，保留 CSS 动画。失败记录不占画廊名额，但错误提示可打开只读执行详情。

### 7. 界面与历史

- 最终 UI 采用用户于 2026-10-25 选定的方案 A「监测总览」：浅色、低饱和绿色强调，顶部汇总指标，下方按监测对象组织卡片；对象卡片内逻辑题时间轴与最新绘图作品并排，窄屏改为纵向排列。保留 Magpie 导航上下文，不采用方案 B 的工作台结构或方案 C 的深色台账结构。
- 使用方案 A 的只读详情、作品放大、历史画廊以及配置和设置弹窗作为交互参考。底部 A/B/C 切换条、原型状态文字和模拟数据标记不进入正式产品；原型仅作为设计依据，正式实现不能直接复用其模拟业务行为。
- 首页以监测对象卡片组织。对象展示目标、推理强度、运行状态、最近和下次执行时间。
- 逻辑题独立展示统计与时间轴；绘图题使用作品展示与历史按钮，不采用逻辑题的通过/失败质量时间轴。
- 逻辑时间轴默认最近 24 小时，可切换 7 天，保留全部配置／仅当前配置筛选。按实际执行记录而非等长时间区间连续展示，从左到右由旧到新；每次自动或手动执行对应独立方格，停机不在真实记录之间插入空格，相邻执行不合并。
- 使用单行热力方格样式：18×18px、间距 3px、圆角 3px；根据逻辑题区域的实际宽度自适应方格数量，不设固定 48／72 条上限。保持单行居右，最新一格贴右，不换行、不横向滚动；窗口变宽时显示更多较早记录，变窄时只保留可容纳的最新记录。
- 不足当前容量时在左侧补浅灰空方格，完全没有记录时整行为空方格，并显示“所选范围暂无记录”。空方格不可点击，不对应时间区间、不代表执行，也不计入统计；真实方格无中央符号，保留原绿色／红色／琥珀色状态背景。
- 标注“展示最近 X 条 / 共 N 条”，只计真实记录，更早记录仍可从执行历史查看。正确率和调用成功率覆盖整个筛选范围，不因展示容量或窗口大小改变；不虚构历史结果。
- 节点提示显示实际开始时间、结果和配置版本，点击直达该次只读执行详情，与执行历史使用同一记录及时间字段。
- 状态在统计、节点提示、可访问名称与只读详情中使用文字说明，不只依赖颜色；热力方格内部不显示文字或图标。UI 可重新设计，不复刻参考网站。
- 逻辑详情展示题目、判分规则、原始回答及判定依据；绘图详情展示作品、题目、原始回答和提取信息。二者均展示当时目标、推理参数、时间和耗时等可获取的信息。
- 历史详情只读，不支持修改题目、答案、原始回答、历史判定或人工评分。
- 默认完整记录保留 5 天，可调整；设置中清楚说明会自动清理。支持 JSON 导出历史和必要快照，不导出访问凭据。
- 异常仅在插件内提示，第一版不提供桌面、邮件或 Webhook 通知。

### 8. 安全与可靠性底线

- 本地服务需校验 Host、请求授权及来源策略。不能把回环地址或 `Origin: null` 本身当作授权，也不能为适配沙盒而允许任意来源访问管理接口。
- 凭据不写入页面资源、历史导出或常规日志。模型生成 HTML 与可信应用资源严格分离。
- 保存历史与配置时考虑进程中断、并发读取、宿主重启和保留期清理；不得使用持续膨胀的页面 options 存储完整历史。
- 页面 options 可用于适合的插件配置，不将其作为通用 RPC 或高频结果数据库。
- 不关闭 Magpie CSP 或父框架沙盒，不通过私有 GUI API 规避插件权限。

## Testing Decisions

用户已确认以下测试边界。测试验证用户与调用者可观察的行为，不断言内部函数拆分、私有字段、数据库布局或具体文件组织。

### 主边界与测试环境

1. 以完整插件为主边界，通过页面及插件自己的服务接口执行配置、启停、运行、历史查询与导出。优先少量高层测试覆盖真实链路，不给 Magpie 核心新增测试接口。
2. 使用隔离的 Magpie/Bun 实例、临时用户目录、配置目录、缓存目录和本地端口。不得读写日常 Magpie、Agent 配置或真实供应商凭据。
3. 使用假 Magpie CLI、假 Codex CLI 和隔离配置测试目录、接入模式、JSONL 用量、延迟、错误和协议失败；如验证真实 Codex CLI，仅连接测试创建的本地模拟网关。测试不访问真实供应商、不消耗付费额度。
4. 使用可控时钟验证周期、错过轮次、恢复、过期和清理，使用可控响应门闩验证串行与超时，不依赖长时间睡眠或脆弱的墙钟阈值。
5. 测试启动的服务、宿主、浏览器页面和后台任务必须在结束时清理。按 Windows 原生工具链运行并记录退出码及实际断言结果。

### 接入与请求契约

- 验证原生 Codex 接入检查、未知／覆盖配置、目录更新与断开；WSL 已接入不能替代原生。断开或无法确认时不再启动测试，保留历史且条件恢复后不补跑。
- 验证公共 CLI 目录快照、完整 ID、推理强度、隐藏项说明排除、更新时间、解析失败与不支持版本；不能接受自由模型 ID、缓存失效后绕过校验或从插件自身 Agent 取模型。
- 验证仅 CLI 可执行、新建默认 CLI、旧直连对象等待明确转换、原 CLI 启停设置保留、插件改名不改内部标识／数据目录；不修改核心或用户 Codex 配置、不回退直连。
- 验证指定模型与路由请求、推理强度、输出上限、请求快照，以及标准答案不外发。
- 验证每次请求无历史上下文、无工具和联网要求；固定题目不被隐式随机化。
- 模拟参数拒绝、401、429、服务错误、超时和截断，确保保留原始错误、不静默修改参数、不额外重试。
- 验证路由目标不冒充实际命中模型；实际信息缺失时明确未知。

### 调度、生命周期和记录

- 验证新建暂停、启用、立即运行、单题运行、每日请求数估算及默认配置。
- 验证停用的逻辑题与绘图题仍可手动单题运行；空闲且接入有效时按钮可用，执行中和接入无效时仍受原有限制。单题运行不改变启停、配置版本或下次执行时间，完整一轮仍只执行启用题目。
- 多对象与手动请求混合时仍全局串行；上轮未完成时跳过新轮，不产生重复执行或无界补跑。
- 暂停后当前请求可完成、后续请求不启动；删除与在途请求完成竞态不复活已删对象。
- 退出、休眠或时间跳跃后仅运行必要的新轮，空档不计模型失败。
- 修改题目、答案、模型等不改变在途轮次、历史快照或旧判定；首页时间轴与画廊不清零，跨配置标记和仅当前配置筛选一致。
- 宿主重启和重叠退役期间只有一个有效调度者；历史可在重启后读取，不能仅验证文件存在。
- 验证 5 天默认保留、调整保留期、清理边界、画廊/详情/导出一致性及写入中断后的数据完整性。

### 逻辑题与绘图

- 使用正确、错误、等价、空白、缺失标记、矛盾或歧义标记、正文包含正确数字但最终答案错误等响应，验证判定依据与界面状态。
- 截断与调用失败不归为答错，正确率和调用成功率各自展示清楚的统计口径。
- 验证完整 HTML、代码围栏、空输出、不可提取内容、截断输出；不静默修复，不把不完整作品当成功作品。
- 验证最新作品、旧图保留及真实时间、空态、错误详情、每题独立画廊和 20/21 张分页边界。
- 验证“创建于”、分钟／k 两位小数、缓存／推理不重复计数、缺失显示“—”、旧配置作品标记；新失败和编辑不会把旧作品的时间／耗时／Token 换成另一条记录。
- 验证原始内容与快照只读，CSS 动画可展示，历史预览不加载当前页以外全部作品。
- 使用含脚本、事件处理器、外部资源、表单、跳转和试图访问父界面内容的 HTML 做安全负例，确保预览不能取得管理权限或向外联网。原型中的单个脚本哨兵不足以替代这些测试。

### 页面与真实桌面验收

- 在真实 Windows WebView2 中验证插件入口、自身导航、握手、页面服务就绪、预览与宿主重启后的恢复。Chrome 中通过不能替代桌面验收。
- 同时保留浏览器中的端到端验证，检查时间轴、只读详情、画廊分页、设置和导出。
- 使用重启后的隔离服务与受控的慢目录请求验证：首页自动刷新一次，等待时已有内容可见、按钮禁用且有旋转图标和状态文字；与编辑弹窗并发刷新只发起一个请求。成功、失败、手动重试与重新加载的反馈均恢复正常，状态轮询不产生额外目录请求，草稿和历史不丢失；覆盖五种语言及窄屏。
- 验证 0 条、12 条及超出容量的执行历史：单行方格数量按逻辑题实际宽度自适应，宽窄窗口往返、绘图列存在与否均正确重算，不换行、不横向滚动；最新记录贴右，不足容量只在左侧补不可点击的灰色空方格。
- 验证手动与定时执行各生成独立节点，真实记录从左到右由旧到新，停机跨时段不插入中间空格；节点提示和点击详情与执行历史使用相同开始时间。统计覆盖完整筛选范围，不受可见格数影响。
- 验证原有绿／红／琥珀状态底色、格内无符号、零记录整行灰格及空态文字、24 小时／7 天与跨配置筛选、五种语言和编辑草稿在窗口变化后保持正常。卡片底部不再显示空档／跳过事件说明，但事件仍保存在导出数据中。
- 对未授权、错误令牌、外部来源、伪造 Host 和 `Origin: null` 分别验证授权策略，测试管理接口与数据接口，不只测试一个读取端点。
- 凭据不得出现在前端可读取状态、历史记录、JSON 导出、生成内容或错误展示中。
- 参考仓库现有的插件页面测试、页面服务权限测试、Bun 宿主生命周期测试、Agent 接入测试以及临时 HOME 隔离惯例；复用其行为验证方式，而不是改动 Magpie 核心来迁就测试。

## Out of Scope

- 修改 Magpie 核心源码、增加私有核心接口或放宽原有安全策略。
- 独立常驻 companion 服务作为第一版部署形态。
- 用其他 LLM 当裁判、开放题语义评分、人工修改历史分数或自动判断绘图美观程度。
- 根据固定题目结果认定供应商换模、掺假或模型整体降智。
- 自动随机题目、动态生成标准答案、自动加随机字符串规避缓存。
- 图片生成 API、强制 PNG 截图与下载、依赖 JavaScript 的绘图或联网素材。
- 插件自身自动重试、离线轮次补跑、并行模型请求。
- 公共展示站点、多用户权限系统、云端同步和外部告警。
- 跨平台兼容承诺；第一版验收目标为用户的 Windows 原生环境。
- 正式开发之外的自动发布、向用户日常实例自动安装、擅自调用付费模型。
- 插件直连网关执行、其他 CLI 后端、通过 WSL 接入替代原生 Codex、自由填写模型、修改 Codex 配置、实时严格同步或完整复刻 Magpie 私有接入判定。
